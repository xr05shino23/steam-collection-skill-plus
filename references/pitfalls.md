# 实战踩坑清单（遇到异常先查这里）

全部来自真实执行一次"四步全流程"的记录，按步骤分组。

## 步骤1 抓取

| 问题 | 现象 | 解法 |
|---|---|---|
| 游戏详情隐私非公开 | 社区 games 页 302 到登录页；Web API 即使有 key 也返回 0 条 | 用 Cookie（浏览器控制登录提取 steamLoginSecure 是最顺滑的方式）；或建议用户把"游戏详情"改公开 |
| 社区页改版 | 页面 200 且已登录但按旧正则抓到 0 条 | 2025 改版后 `rgGames` 没了，改用内嵌 React Query JSON 数据块解析（`"name"` 与 `"store_url_path":"app/<id>"` 紧邻配对）；两种结构都要兼容 |
| 个人资料装饰品混入 | 解析出 appid 0 / 商城物品 | 过滤 appid 0；`store_url_path` 必须以 `app/` 开头；name 字符集排除 `\` 和 `"` 防跨嵌套误抓 |
| Playwright goto 超时 | 打开社区页 45s 超时但网络正常 | 默认等 `load` 事件被慢资源卡死；改 `wait_until="domcontentloaded"` |
| playwright 装不上 | pip 卡死无输出 | 国内环境：直连清华镜像 **不要套代理**（`pip install playwright -i https://pypi.tuna.tsinghua.edu.cn/simple`）；代理只需给浏览器/请求用 |
| SSL error / EOF | 请求偶发 `SSLEOFError` | 代理节点抖动，脚本带指数退避重试即可 |
| 游戏详情页区域不可用 | 商店页返回"区域不可用" | 换 steamdb 或搜索引擎核实 |
| 228980 之类的条目 | manifest 里有 Steamworks Common Redistributables | 系统组件维护一个过滤名单；"有 manifest 但无所有权"的条目（家庭共享残留）只报告不写入 |
| 主会话工具也被限流 | agent 自己的 WebSearch 报 concurrency exceeded | 子代理占满并发时主会话的网络工具同样受限；错峰做自己的搜索 |

## 步骤2 预分类

| 问题 | 现象 | 解法 |
|---|---|---|
| Steam 标签泛滥 | 大量游戏 C 类型 6+ 个、明显不符（动作 FPS 被标"模拟经营+开放世界+战棋"） | 预分类只求覆盖不求精准；步骤3 复核才是质量主力 |
| 兜底类不在最后 | "其他"类排在中间，收藏集列表难看 | 编号规范：兜底用大类内最大号（D99）并与主编号留空档；主编号连续 |
| 编号空位 | 删除/新增类目后 D42 空缺 | 重编号时**单次映射**（43→42, 44→43 … 同一遍扫描），严禁顺序替换（会链式覆盖）；注意 `'D43'.isdigit()` 是 False，要取 `x[1:]` 再判 |
| 新增类目忘同步 | 部分脚本用旧编号 | 类目定义、规则文件、生成脚本的 NAMES/ORDER 三处必须同一提交里改完 |

## 步骤3 复核

| 问题 | 现象 | 解法 |
|---|---|---|
| 子代理并发上限 | 第 3 个子代理被杀（user concurrency limit exceeded） | 实测上限 2；先双发试探，被拒就回落双路流水线：完成一个立刻补派下一个 |
| 子代理写错分隔符 | 结果文件用 `\|` 而不是逗号；merge 全部漏接 | merge 前跑格式校验脚本（见 methods-review.md），竖线行按 `\|` 重组 |
| 子代理漏空列 | 6 列/5 列行，空值列被省略 | 校验脚本按模式补齐（6 列补 B、5 列补 E+是否确定） |
| 子代理加值前缀 | 字段是 `C=C06;C13` 而不是 `C06;C13` | 校验脚本剥离 `B=`/`C=`/`D=`/`E=` 前缀；`-` 转 `` |
| 子代理上下文爆炸 | 同一批次固定位置崩溃（Model returned no text） | 该批拆两半；提示词加护栏（WebFetch 每款 1 次失败即弃、禁重试、禁中途总结） |
| 子代理中断 | 进程被杀/超时 | 提示词要求每 5 款重写一次结果文件（增量保存）；重派同一批即可续跑 |
| 服务商过载 | Start Plan is busy / quota limit | 等几分钟重试；个别顽固款由主会话亲自搜索兜底 |
| 结果行数对不上 | merge 覆盖数 < 批次总数 | 逐项诊断：未知 appid / 短行 / 列数异常，分类修复后再 merge |

## 步骤4 写入

| 问题 | 现象 | 解法 |
|---|---|---|
| Steam 未退净 | 守卫 REFUSE | 托盘里 steamwebhelper/steamservice 也要退；守卫三重检测（进程/注册表/tasklist） |
| 写入后收藏集消失/不显示 | key 重复或 JSON 非法被客户端忽略 | 写入前双重 json 校验 + key 去重断言；用备份回滚重写 |
| 长期会话过期 | 数月后 Cookie 失效 | 重新跑一次浏览器登录流程 |

## 增量模式

| 问题 | 现象 | 解法 |
|---|---|---|
| 新装游戏没有 A 状态 | "正在玩/计划玩"收藏集里找不到新游戏 | A 是用户个人状态，detect 后必须问用户或按 categories.md 默认档填进 new_rows.csv 再 merge/apply；apply 会逐条列出"需指定 A" |
| A 状态残留在已卸载游戏上 | 未安装游戏出现在状态收藏集 | apply 自动同步 installed 列并清空 installed=false 行的 A；不要手工只改一列 |
| 新款查不到元数据 | steamcmd 返回 _missing/无 store_tags（测试款/区域限制） | 按名称 WebSearch 分类；仍定不了 C 的进待确认表，不硬编 |
| 标签列是数字 ID | steamcmd 的 store_tags 是 id，批次行不可读 | fetch-info 首次自动抓 populartags 生成 data/steam_tags_map.json 并转换；抓不到（需代理）时保留 ID，子代理按名称自行搜索 |
| 移除的游戏还在收藏集里 | 退款/移除的款仍出现在 Steam 收藏集成员里 | 无害（Steam 忽略不存在的 appid）；要彻底清掉用 `apply --prune` |
| 重复跑增量产生重复行 | 同一 appid 追加两次 | 不会：apply 按 appid 覆盖/追加去重；总表是唯一基准，不设独立 state 文件 |

## 分类质量（实战新增）

| 问题 | 现象 | 解法 |
|---|---|---|
| 泛化类互相吸收 | 每款平均挂 3-5 个类型；「冒险/休闲/合作」装了大半个库 | 跑 `overlap_check.py` 体检；对高重叠泛化类做「准入+排除+锚点」（`category-quality.md`）；只收泛化类，勿全类目一刀切 |
| 属性被当类型 | 「多人合作」与动作重叠 0.34，跟谁都沾边 | 把属性迁成 **F 特性**维度（`C19 多人合作 → F01`），从根上消除互吸 |
| 子代理列错位 | 结果里"依据"写"保留休闲"、判定却填了"冒险" | merge 前抽查"依据↔结论"自洽；**双遍交叉**比对（`compare_passes.py`） |
| 单遍复核不稳 | 同批同口径跑两遍仍有 ~11% 不一致 | 双遍交叉 + 冲突处理三选一（用户拍板/第三遍/多数表决） |
| 标签泛滥 | 商店标签"有就加"导致虚胖 | 标签按**顺序/占比**取（只认前 5 个），而非有/无 |
| 厂商兜底类变垃圾桶 | D99 里混着名厂、中国厂商、长尾 | 见 `vendor-region.md`：联网判国别 + 名厂逐个独立成类 |
| 厂商名判断地区不可靠 | 中文名/英文名都会骗人（`AsicxArt`=成都） | **必须联网核实**；占位串（"本游戏已经下架退市"）不得当厂商 |

## 会话与工程（实战新增）

| 问题 | 现象 | 解法 |
|---|---|---|
| 长会话思维循环 | 跑几百条消息后开始重复、原地打转 | 每步收尾 `handoff.py --write` 刷新 `HANDOFF.md`；上下文将满时**先落盘再换窗口**，新窗口只读 HANDOFF 接续 |

## 通用

- 一切覆盖写操作前先备份（旧表/目标文件），时间戳命名
- 产出 CSV 统一 UTF-8 with BOM（Excel 友好）；agent 内部处理时记得 `utf-8-sig` 读取
- 每一步完成后**停下来汇报等确认**，不要自作主张连跑
