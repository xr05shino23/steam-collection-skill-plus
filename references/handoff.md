# 会话接续：状态外置与 HANDOFF 协议

## 为什么需要

四步流程 + 联网复核动辄几小时、几十个子代理、几百次工具调用。**上下文越堆越长**，
模型会开始**原地打转、思维循环**（真实案例：一次全流程跑到 300+ 条消息后开始重复，被迫换窗口）。

解决办法不是"更努力记住"，而是**把状态写到磁盘**：任何时候新开一个窗口，**只读一份文档**就能无损接续。

## 原则

1. **状态外置**：进度、决策、口径、文件清单都落盘，不依赖对话记忆。
2. **频繁刷新**：每个步骤收尾、每次重大决定后都更新一次。
3. **只读它就能接续**：HANDOFF 必须自足——新窗口读它就够，不需要翻旧对话。
4. **不塞敏感信息进仓库**：`HANDOFF.md` 含 SteamID/本机路径，应加入 `.gitignore`。

## 何时生成 / 更新

- 每个步骤（1→2→3→4）完成后；
- 用户做出重要决策后（改类目、改口径、确认写入）；
- **上下文接近上限、感觉要开始打转时**——先落盘，再换窗口。

## HANDOFF.md 结构（模板）

```markdown
# <项目> 交接文档（HANDOFF）
> 新窗口先读本文件即可无损接续。生成时间：<时间>

## 一句话状态
<现在到哪一步了、下一步是什么、有没有"严禁"事项>

## 工作区
- 路径 / git 分支 / 远端

## 关键文件
| 文件 | 说明 |

## 已确认的决策
1. ...（用户拍板过的，逐条）

## 下一步（新窗口从这里继续）
1. ...

## 注意事项 / 已知坑
- 凭据、写入守卫、回滚备份路径、`userdata` 用 SteamID32 等
```

## 工具

`scripts/handoff.py` 自动生成骨架（阶段产物、备份、类目/收藏集计数、git 分支）：

```bash
python scripts/handoff.py                 # 打印骨架到终端
python scripts/handoff.py --write         # 写入 HANDOFF.md
python scripts/handoff.py --write --note "已写入 Steam（135 个收藏集）"
```

> 自动部分只填**事实**（有哪些文件、多少类目、最近备份）；**决策与下一步**需要 agent/用户补全。
> 工具是**幂等**的：重复运行只刷新事实区，`--note` 追加一条更新记录。

## 给 agent 的要求

- 每个步骤结束，调用一次 `handoff.py --write --note "..."`，并**人工补全"决策/下一步"两节**。
- 向用户汇报时，附上一句"HANDOFF 已更新"。
- 若发现上下文开始变长/重复，主动建议用户：**先更新 HANDOFF，再开新窗口**。
