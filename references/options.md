# 分类策略档位（把选择交给用户）

开工前（或步骤 2 之前）让用户在下面 5 个维度上选档，agent 照此调整步骤 2/3 的行为。
**一次问完**，不要中途反复问。

| 维度 | 选项 | 影响 |
|---|---|---|
| **精细度** | 精简 / 标准 / 宽松 | C 类型每款上限 |
| **属性维度** | 关 / 开 | 是否启用 F 特性（多人合作/VR/手柄…） |
| **泛化类收紧** | 关 / 开 | 是否做类目体检 + 准入/排除收紧 |
| **复核深度** | 不复核 / 只查可疑款 / 全量 / 全量双遍交叉 | 步骤 3 子代理规模与轮次 |
| **预算与并发** | 低 / 中 / 高 | 批次大小与并发（运行时探测上限） |

## 各档说明

**精细度**
- **精简**：每款只留 **1 个主类型**（最具代表性的玩法）。区分度最高，但丢掉"顺带也属于"的信息。
- **标准（推荐）**：**1 个主类型 + 至多 2 个次要**。兼顾区分度与信息量。
- **宽松**：多选不限（最容易"虚胖"，配合「泛化类收紧」使用）。

**属性维度**
- **开**：把「多人合作、本地同屏、VR、支持手柄、成就、云存档」等**属性**放进 F 维度，
  不污染 C 类型（推荐，见 `categories-guide.md`）。
- **关**：不建属性收藏集，F 列留空。

**泛化类收紧**
- **开**：对「动作/冒险/休闲/RPG/策略/生存…」等**高重叠泛化类**做体检 + 准入/排除收紧
  （见 `category-quality.md`）。只收泛化类，**不要全类目一刀切**。
- **关**：跳过，直接采用预分类/复核结果。

**复核深度**（成本由低到高）
| 档 | 做什么 | 适用 |
|---|---|---|
| 不复核 | 跳过步骤 3 | 只想要个大概 |
| 只查可疑款 | 只复核待确认 + 类数异常 + 用户常玩的 | 预算有限 |
| 全量 | 全部游戏走一遍子代理 | 想要准 |
| **全量双遍交叉** | 同一批跑两遍、逐款比对、冲突人工定夺 | 最准，成本翻倍（见 `methods-review.md`） |

**预算与并发**：低/中/高映射到批次大小与并发数；不确定时按 `methods-review.md` 的探测协议
（先双发探测上限，被拒即回落）。

## 建议默认

> 标准 · 属性开 · 收紧先"体检后决定" · 只查可疑款 · 中

## 与步骤的对应

- 步骤 0（开工前）收集这些选择；
- 步骤 2：按"精细度/属性维度/收紧"生成类目与预分类；
- 步骤 3：按"复核深度/预算"决定子代理批次与轮次；
- 步骤 4：与档位无关，照常写前确认 + 写入。
