# 类目体检：重叠矩阵 + 准入/排除 + 锚点

分类做完（甚至复核后）并不意味着"准"。真正的偏差往往出在**泛化类目互相吸收**：
「冒险」「休闲」「动作」「合作」这类宽泛标签几乎处处都有，结果**每款游戏挂 3–5 个类**，
每个收藏集都装了一大半库，失去筛选价值。

## 体检指标（先量化，再动手）

1. **每款游戏的类数分布**：理想是多数 1–2 个、少数 3 个。
   真实案例：某库 602 款平均 **3.7** 个（挂 4–5 个的有 359 款）——明显虚胖。
2. **两两类目的重叠（Jaccard）**：`|A∩B| / |A∪B|`。越高越说明两类在互相吸收。
3. **各类目成员数**：过大且内部异质 → 考虑拆分；过小 → 考虑合并。

```bash
python scripts/overlap_check.py --group C            # 体检 C 维度
python scripts/overlap_check.py --group C --write    # 写 step2/overlap_matrix.md
python scripts/overlap_check.py --group D --threshold 0.3
```

**告警阈值经验**：`Jaccard > 0.25` 视为"可能互相吸收"，值得人工看一眼。
但**高重叠不总是错**——例如「视觉小说 + 冒险」本就该重叠（很多 VN 就是叙事冒险）。
判断标准：重叠的是"泛化兜底类"（该拆）还是"本来就相邻的类型"（可留）。

## 收紧方法：准入 + 排除 + 锚点

给每个要收紧的类目写**三件套**（写进 `categories.md`）：

```
- C13 类型-休闲
  准入: 轻量、低门槛、以休闲为主
  排除: 以战斗/竞技/生存/大RPG为主
  锚点: 留=胡闹厨房 / Beat Saber；去=求生之路
```

- **准入**：什么是这类；**排除**：什么不算（最关键，专治泛化类互吸）；
- **锚点**：每类 3–5 个"典型/边界/反例"，作为复核子代理的 few-shot，显著降低分歧。

然后只对**参与高重叠对的成员**联网复核（不必全库重跑），按诊断 → 收紧 → 复检。

## 成效参考（真实一次）

对 8 个泛化类（动作/角色扮演/策略/模拟经营/解谜/恐怖/生存/沙盒）做准入+排除收紧后：

- 平均每款类数 **3.7 → 2.34**；挂 4–5 个类的从 359 款降到 77 款；
- 恐怖+生存重叠 0.33→0.24；策略+模拟经营 0.25→跌出前 12。

## 两个别踩的坑

1. **不要"越删越准"**：收紧可能误删合法成员（如"剧情向动作"到底算不算冒险）。
   每次收紧都要能回滚，并保留"锚点"备查。
2. **不要全类目一刀切**：只收紧**高重叠 + 泛化**的少数类；具体类（射击/竞速/塔防）重叠低，动它反而制造错误。

## 与属性维度的关系

有些"泛化类"其实是**属性**而非类型（如「多人合作」）。与其在类型里收紧，不如把它拆成
独立维度（见 `categories-guide.md` 的 F 特性），从根上消除互吸。
